# 작업 복기 (Recap)

`/clear` 직전에 실행한다. 최근 작업 최대 3개를 분석해 사용자에게 보여주고,
어떤 작업을 핸드오프할지 선택받은 뒤 `.claude/handoff.md`에 저장한다.
다음 세션 시작 시 이 파일이 자동으로 읽혀 맥락을 복기한다.

---

## 절차

### 1단계 — git 상태 수집 (병렬)

다음을 동시에 실행한다:
- `git status --short`
- `git log --oneline -20`
- `git log --oneline main..HEAD`
- `git diff --stat HEAD`

### 2단계 — 작업 그룹 식별 (최대 3개)

커밋 이력과 uncommitted 변경을 종합해 **주제별 작업 그룹**을 최대 3개 추출한다.

**그룹 분류 기준 (우선순위 순):**
1. uncommitted 변경이 있으면 → 반드시 **그룹 1 "현재 작업 중 (미커밋)"** 으로 추가
2. 커밋 메시지 + 변경 파일 영역이 유사한 커밋들을 하나의 그룹으로 묶는다
   - 같은 페이지/도메인(예: `applications/`, `reminders/`, `semesters/`) → 같은 그룹
   - 같은 날짜 내 연속 커밋 → 묶음 판단 우선
3. 3그룹이 안 되면 있는 만큼만 표시 (최소 1개)

각 그룹에 대해 파악한다:
- 그룹 제목 (무엇을 했는가 — 10자 이내)
- 포함 커밋 수 / 날짜
- 핵심 변경 파일 (최대 3개)
- 한 줄 요약

### 3단계 — 선택지 출력 후 대기

아래 포맷으로 출력한 뒤 **반드시 사용자의 답변을 기다린다. 핸드오프 파일을 먼저 쓰지 않는다.**

---

## 🗂️ 핸드오프할 작업을 선택하세요

**브랜치**: `{branch}` · main 대비 +{N}커밋

| # | 작업 | 커밋 | 날짜 | 핵심 파일 |
|---|------|------|------|-----------|
| 1 | {그룹1 제목} | {N}개 | {날짜} | {파일1}, {파일2} |
| 2 | {그룹2 제목} | {N}개 | {날짜} | {파일1}, {파일2} |
| 3 | {그룹3 제목} | {N}개 | {날짜} | {파일1}, {파일2} |

**어떤 작업을 핸드오프할까요?** (1 / 2 / 3)

---

### 4단계 — 선택된 작업으로 핸드오프 파일 저장

사용자가 번호를 입력하면, 해당 그룹 정보를 바탕으로 아래 형식의 `.claude/handoff.md`를 Write한다.

```markdown
# Handoff — {날짜} {시각}

## 브랜치
`{branch}` · main 대비 +{N}커밋

## 선택된 작업: {그룹 제목}

### 무엇을 했는가
{선택된 그룹의 커밋 목록 + 변경 내용 3-6줄 불릿}

### 미완료 변경
{uncommitted 파일 목록, 없으면 "없음"}

### 다음 단계
{해당 작업에서 이어서 해야 할 것 — 1줄}

### 복귀 시 열어야 할 파일
1. {파일 경로}
2. {파일 경로}
3. {파일 경로}
```

저장 후 출력:

> ✅ `.claude/handoff.md` 저장 완료 — 이제 `/clear` 해도 됩니다.

---

## 행동 규칙

- **3단계에서 반드시 멈추고 사용자 응답을 기다린다.** 먼저 파일을 쓰지 않는다.
- 그룹이 1개뿐이라면 선택 없이 바로 확인 후 저장한다: "작업이 1개뿐입니다. 이걸로 핸드오프할까요? (y/n)"
- 코드를 수정하지 않는다. `.claude/handoff.md` 저장만 예외.
- 한국어로 응답한다.
- uncommitted 변경이 없고 새 커밋도 없으면 "변경 없음 — 핸드오프할 작업이 없습니다"를 출력하고 종료.
